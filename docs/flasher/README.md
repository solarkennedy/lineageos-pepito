# Palm PVG100 flasher

A static web page that backs up and flashes a Palm PVG100 or PVG100E over
Qualcomm EDL (9008) using WebUSB. Its instructions lead with the pepito
LineageOS 24 release, but it flashes any ROM supplied as raw images. No build step, no dependencies: plain ES modules.

Status: first run on hardware 2026-10-11, on a PVG100 (unit 9c2e6b00) from
Brave on Linux. A full backup matched an earlier `qdl-dump.sh` dump of the same
unit on every partition that had not changed since, and a flash of a 24.0 build
booted. Reads ran at about 5 MiB/s. Not yet run on a PVG100E, on Windows or on
macOS.

## Run it locally

The flasher is only static files. It needs some web server because WebUSB and
ES modules do not work from `file://`; any static server will do, and
`localhost` counts as a secure context:

    python3 -m http.server 8100 --bind 127.0.0.1

Open http://localhost:8100/ in Chrome or Edge. The page walks the user through
downloading the release zip, extracting it and running `ota2raw`, then reads
the images from the zip's `edl/` folder: `boot.bin`, `recovery.bin`, `system.bin`, `vendor.bin`,
`pvg100_firehose.elf`, `pvg100e_firehose.elf` and optionally `boot-magisk.bin`.
Nothing is uploaded, and the page never fetches images over the network.

## What it does

1. The user chooses PVG100 or PVG100E.
2. Sends that variant's programmer, then reads the phone's partition table.
   The boot ROM only accepts the programmer signed for its own variant.
3. Refuses to continue unless the table matches the chosen variant's layout
   (`js/layouts.js`).
4. Writes `boot`, `recovery`, `system` and `vendor` and zero-fills `config`, at
   the offsets in the phone's own partition table. That list is fixed in
   `js/device.js`; a build cannot add to it.

Before flashing, "Back up to a folder" reads every partition except userdata
into `<partition>.bin` files plus `gpt-lun0.bin` and `rawprogram_restore.xml`,
the same layout `scripts/qdl-dump.sh` produces. Restoring is done with `qdl`:

    qdl --storage emmc --include <backup dir> pvg100_firehose.elf <backup dir>/rawprogram_restore.xml

Neither rawprogram XML is used at flash time, so the wrong-XML mistake that
overwrites bootloader or modem NV on the other variant cannot happen here.

## Layout

| File | Role |
|---|---|
| `js/usb.js` | WebUSB transport |
| `js/sahara.js` | boot ROM protocol: send programmer |
| `js/firehose.js` | programmer protocol: configure, read, program, reset |
| `js/gpt.js` | partition table reader |
| `js/layouts.js` | known layouts, generated by `tools/gen-layouts.py` |
| `js/flash.js` | the procedure: connect, plan, flash |
| `js/sources.js` | image source: a folder on disk |
| `loaders/` | the two signed Firehose loaders, one per model |
| `js/os.js` | shows only the instructions for the visitor's operating system |
| `js/app.js` | page logic |

## Host setup

- **Linux:** the user needs access to the 05c6:9008 USB device (a udev rule),
  and the `qcserial` kernel driver must not hold it. The page shows the unbind
  command under "Connection trouble".
- **Windows:** the phone must be bound to WinUSB (Zadig), not the Qualcomm
  9008 serial driver.
- **macOS, ChromeOS, Android:** expected to work without setup; untested.

## Hosting

Served by GitHub Pages from this branch's `/docs` folder, so it is published at
`https://solarkennedy.github.io/lineageos-pepito/flasher/`. It lives only on
the `lineageos24.0` branch: the page's instructions assume the 24.0 release
zip (update payload plus `edl/` kit and `ota2raw`), not the 23.2 `.tar.xz`.

The page never fetches images over the network. GitHub release downloads send
no CORS headers, so it could not if it tried; the user downloads the zip and
points the page at the extracted folder.
