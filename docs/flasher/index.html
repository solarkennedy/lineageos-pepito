Palm PVG100 flasher

Backs up and flashes a Palm PVG100 or PVG100E over USB, straight from this page. The steps below install LineageOS 24 (Android 17); other ROMs work the same way. It needs Chrome, Edge or another Chromium browser on a desktop computer; Firefox and Safari cannot talk to USB devices.

Flashing this phone for the first time? Back it up first. The backup holds the stock firmware and this phone's own radio calibration, and it is the only way back to stock.

Get the ROM

  1. Download the LineageOS 24 zip from the releases page: the file named lineage-24.0-…​.zip (over 1 GB). Pick the one with gapps in its name if you want Google apps.
  2. Extract the zip to a folder. Windows: right-click it and choose Extract All. Linux and macOS: unzip lineage-24.0-*.zip -d lineage-pepito. You need about 7 GB free, counting the zip itself.
  3. Open the edl folder inside it and run the converter, ota2raw, for your computer. It builds the images this page flashes and takes a minute or two. Windows: double-click ota2raw-windows-x86_64.exe. Linux: run ./ota2raw-linux-x86_64 in a terminal. macOS: run ./ota2raw-macos-arm64 in Terminal. The exact commands are under "Running the converter" below.
  4. Press the button below and choose that edl folder.

Running the converter (ota2raw)

The zip is an update package: it holds the system in a compressed form that only a running phone can install. ota2raw turns that into the plain images a first install needs, and checks each one against a known checksum. It prints verified for each image.

The edl folder has one converter per kind of computer. Run the one that matches yours.

Windows

Double-click ota2raw-windows-x86_64.exe. Windows may warn that it is an unrecognised app, because it is not code-signed: choose More info, then Run anyway. Wait for Done.

Linux (use ota2raw-linux-arm64 on an ARM machine)

cd lineage-pepito/edl
chmod +x ota2raw-linux-x86_64
./ota2raw-linux-x86_64

macOS (use ota2raw-macos-x86_64 on an Intel Mac)

cd lineage-pepito/edl
xattr -dr com.apple.quarantine .
chmod +x ota2raw-macos-arm64
./ota2raw-macos-arm64

The xattr line clears the quarantine flag macOS puts on downloaded programs.

Afterwards the edl folder contains boot.bin, recovery.bin, system.bin and vendor.bin next to the two loaders (pvg100_firehose.elf, pvg100e_firehose.elf). Those are the files this page reads. The other files in the folder are for the command-line method and are ignored here.

Other ROMs and stock firmware

Every known firmware for this phone, stock and third-party, is listed in the XDA firmware thread.

This page can flash any of them, within what it writes. The folder you choose must contain boot, recovery, system and vendor images, named boot.bin or boot.img and so on.

The images must be raw, not Android "sparse" images. This page refuses a sparse image; convert it first with simg2img.

Only those four partitions are written, and config is cleared. A stock firmware package also carries the bootloader, modem and other firmware; this page leaves those as they are. To put a phone fully back to stock, restore your own backup on the Restore tab.

Which download?

Each release has two zips. Take one, not both:

  • the plain one: LineageOS with no Google apps;
  • the one with gapps in its name: the same build with Google apps and the Play Store.

The same zip is also the update package. A phone that already runs this LineageOS does not need this page: its built-in Updater installs the zip directly.

To check the download is intact, fetch the matching .sha256sum file into the same folder and run sha256sum -c lineage-24.0-*.zip.sha256sum.

About the root option

Ticking the box installs boot-magisk.bin, this build's boot image with Magisk already patched in. Root is optional and unsupported.

  • You cannot make your own by patching boot.bin in the Magisk app. The result is unsigned and the phone hangs at the PALM logo.
  • After the first boot, install the Magisk app and let it finish its "additional setup".
  • Never use Magisk's Direct Install to update. It breaks the boot image, and the only fix is to flash again from this page.
  • Switching between rooted and unrooted later keeps your data: flash again with the box changed.

Connect the phone

  1. Put the phone in EDL mode, using one of the ways listed below. The screen goes black and stays black.
  2. Check the model below. PVG100 is the US model; PVG100E is the international one.
  3. Press Connect and pick QUSB_BULK or QHSUSB__BULK from the list.

Ways to get into EDL mode

EDL (emergency download, also called 9008 mode) is a mode built into the phone's chip. The screen is black and the phone looks dead; that is normal. There are three ways in.

1. From recovery

Hold the power button down through three restarts, until "Entering Recovery Mode" appears. Then:

  • LineageOS recovery: choose Advanced, then Reboot to EDL. The menu works by touch or with the power button.
  • Stock recovery: choose Emergency Download Mode in the main menu. Use the power button: a short press moves down, a long press selects.

From stock recovery:

Watch the video on YouTube

2. With adb

  1. Open Settings, About phone, and tap Build number seven times to unlock Developer options.
  2. In Developer options, turn on USB debugging.
  3. Plug the phone into the computer and accept the "Allow USB debugging?" prompt on the phone.
  4. Run adb reboot edl.

adb comes with Google's platform-tools. It works from Android and from recovery.

3. With an EDL cable

An EDL cable (also sold as a "deep flash cable") is a USB cable with a button on it. It works on a phone that will not start at all.

  1. Turn the phone off: hold the power button for about 15 seconds.
  2. Hold the cable's button down and plug the cable into the phone.
  3. Let go of the button after a few seconds.

Checking it worked

  • Linux: lsusb lists a Qualcomm device with ID 05c6:9008.
  • macOS: System Information, USB, shows QUSB_BULK.
  • Windows: Device Manager shows a Qualcomm 9008 device or QUSB_BULK.

Getting out again

Press "Restart the phone" once connected, or hold the power button for about 15 seconds. Leaving EDL without flashing changes nothing on the phone.

Use a plain USB cable plugged straight into the computer. Hubs and magnetic adapters drop connections.

Which model do I have?
  • PVG100: the US (Verizon) model.
  • PVG100E: the international (Vodafone) model.

The model number is printed on the label on the back of the phone and on the box. Stock Android shows it under Settings, System, About phone, Model.

Both models take the same build, but each only accepts its own loader and they lay out storage differently. If you pick the wrong one the phone refuses the loader, or this page stops at the partition check. Either way nothing is written.

Connection trouble

Linux: if Connect reports "Access denied", the browser is not allowed to open the phone. Add a udev rule, then unplug the phone and plug it back in: 

echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="05c6", ATTR{idProduct}=="9008", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/70-qualcomm-edl.rules
sudo udevadm control --reload-rules

If Connect fails to claim the interface instead, the qcserial driver has taken the phone. Release it with: 

for d in /sys/bus/usb/drivers/qcserial/*-*; do echo "${d##*/}" | sudo tee /sys/bus/usb/drivers/qcserial/unbind; done

Windows: the phone must use the WinUSB driver, not the Qualcomm 9008 serial driver. Zadig can switch it. The command-line qdl method needs the serial driver instead, so switch it back if you change methods.

Nothing in the list after pressing Connect: the phone is not in EDL mode, or the cable carries power only. Check with the steps under "Ways to get into EDL mode".

If a step fails part-way, hold power for about 15 seconds, re-enter EDL mode and reload this page.

Back up the phone

Copies every partition except your personal data to a folder on this computer: the stock firmware, the bootloader and the modem calibration that is unique to this phone. It is the only way back to stock, so do it once before the first flash. It needs about 8 GB of disk space.

What is in a backup, and how to restore one

The backup is a new folder named palm-<model>-backup-<date> inside the folder you choose. It contains:

  • one .bin file per partition, about 50 in all;
  • gpt-lun0.bin, the partition table;
  • rawprogram_restore.xml, the list a restore tool needs to put each file back.

Some of these files exist nowhere else. modemst1, modemst2, fsg, persist, sec and traceability hold this phone's own radio calibration and identity. Without them a phone cannot be returned to working stock firmware.

Your personal data (userdata) is left out. It is most of the storage, it is encrypted, and it cannot be read back on a phone that has been reflashed.

Restoring is done on the Restore tab. The qdl command-line tool can also do it, with the phone in EDL mode, from the folder that holds the loader: 

qdl --storage emmc --include palm-pvg100-backup-DATE pvg100_firehose.elf palm-pvg100-backup-DATE/rawprogram_restore.xml

On a PVG100E use pvg100e_firehose.elf.

Copy the finished folder somewhere safe.

Back up one partition

Reads a single partition from the phone and saves it as a file on this computer. Nothing on the phone is changed.

What the file holds

The whole partition, byte for byte, in a file named after it, such as modemst1.bin. That is the same file a full backup holds, so the Restore and Flash (advanced) tabs take it back as it is. "Partition table" saves gpt-lun0.bin, the first 34 sectors of the storage.

userdata is most of the storage, over 20 GB, and encrypted: a copy cannot be read on another phone, or on this one once it has been reflashed.

Restore a backup

Writes partition images from a folder back to the phone: a whole backup from the Back up tab, to return to stock or undo a flash, or just the files you need, such as a single boot.bin or boot.img. Each file goes to the partition it is named after; partitions with no file are left as they are.

The partitions that hold this phone's own identity and calibration are only written from a backup of this same phone. The page checks the folder's traceability.bin against the phone's factory record first, and skips them when the folder has none.

The phone restarts when the restore finishes.

What a restore writes, and what comes after

A file is matched to a partition by its name: boot.bin or boot.img goes to boot, modemst1.bin to modemst1. Files must be raw images no larger than their partition, not Android "sparse" images (convert those with simg2img). Other files in the folder are ignored. A whole backup is about 8 GB and takes longer than a flash. Your personal data (userdata) is never written.

If the folder holds a gpt-lun0.bin or traceability.bin, they must match this phone, or nothing is written: the folder is a backup of a different phone.

After restoring stock firmware, the data LineageOS left behind cannot be read by stock Android. If the phone stays on the boot logo or asks to reset, open stock recovery (hold the power button down through three restarts) and choose Wipe data/factory reset. It erases everything on the phone.

The restore stopped part-way: leave the phone connected and press Restore again. If the page lost the connection, put the phone back into EDL mode, reload this page and start again. A phone whose bootloader is only half-written goes into EDL mode on its own when switched on; failing that, an EDL cable always works.

Why some partitions need proof: traceability, modemst1, modemst2, fsg, ssd, persist, tunning, simlock and DDR belong to one phone: its identity, radio and sensor calibration. Writing another phone's would give this one the other's identity and a radio tuned for different hardware.

Write one image

Writes a single image file to the partition you choose. The page checks only that the file is a raw image that fits; it cannot tell whether the image belongs in that partition, or on this phone. Use it when you know exactly which file goes where, and back up first.

The phone stays in EDL mode, so more images can follow. Restart it when done.

What this writes, and the risks

The file is written from the start of the partition. A file smaller than the partition leaves the rest of it as it was. Nothing else on the phone is touched. Images may be named anything; if the name matches a partition, such as aboot.img or modemst1.bin, that partition is chosen for you.

Bootloader partitions (sbl1, aboot, rpm, tz and others): a wrong image stops the phone from starting. It then goes into EDL mode on its own, or with an EDL cable, so it can be rewritten here.

Per-phone partitions (traceability, modemst1, modemst2, fsg, ssd, persist, tunning, simlock, DDR) hold this phone's own identity and calibration. Only write a copy taken from this same phone. Another phone's copy gives this one its identity and a radio tuned for different hardware. The page asks you to type the partition's name before writing one. The Restore tab can check a whole backup's origin; this tab cannot.

Flash

Writes boot, recovery, system and vendor, and clears config.

The phone restarts when the flash finishes.

If the flash or the first boot goes wrong

The first boot takes a few minutes. Leave the phone alone while the boot logo animates.

Black screen for more than five minutes: put the phone back into EDL mode and flash again. Flashing twice does no harm.

The flash stopped part-way: leave the phone connected and press Flash again. If the page lost the connection, hold power for about 15 seconds, re-enter EDL mode, reload this page and choose the folder again.

Erase data (optional)

Only needed after a major change: coming from stock firmware, switching to a different ROM, or a major version upgrade. Skip it when updating to a newer build of the ROM already on the phone. It erases everything on the phone.

  1. Hold the power button down through three restarts, until "Entering Recovery Mode" appears. The recovery menu works by touch.
  2. Choose Factory reset, then Format data.
  3. Choose Reboot system now.

What each partition holds

The phone's storage is divided into partitions, each with one job. Sizes are for the PVG100, then the PVG100E where it differs. The tags say which partitions the Flash tab writes and which are part of the bootloader.

"Unique" says whether a partition's contents differ from one phone to the next, found by comparing the backups of eight phones. The unique ones exist only in your phone and in your backup of it: no download or other phone can replace them. "Per firmware" partitions are the same on every phone with the same stock firmware version, and "per ROM" ones on every phone with the same ROM installed.
